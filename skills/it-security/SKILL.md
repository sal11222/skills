# IT & Security

## When to use this skill

Use this skill for tasks such as:
- Writing or reviewing security policies and procedures
- Threat modeling and risk assessments
- Incident response planning and playbooks
- Security awareness content and training materials
- Vulnerability analysis and remediation guidance
- Access control and identity management guidance
- Compliance checklists (SOC 2, ISO 27001, NIST, CIS Controls, etc.)
- Security architecture reviews
- Penetration testing scoping and reporting

## How to use this skill

1. **Identify the security task** from the request (policy writing, threat model, incident response, etc.)
2. **Gather context** – ask for the environment type (cloud, on-prem, hybrid), industry/regulatory requirements, and audience if not provided
3. **Apply the relevant framework** – align output to widely accepted standards (NIST CSF, MITRE ATT&CK, CIS Controls, ISO 27001) where appropriate
4. **Produce structured, actionable output** – use clear headings, risk ratings, and recommended actions

## Output guidelines

- **Policies**: Include purpose, scope, roles and responsibilities, policy statements, enforcement, and review cadence
- **Threat models**: Use a structured format (e.g., STRIDE or PASTA) with assets, threats, likelihood, impact, and mitigations
- **Incident response playbooks**: Include detection, containment, eradication, recovery, and lessons-learned phases
- **Risk assessments**: Rate risks by likelihood × impact, and prioritize by business criticality
- **Compliance checklists**: Map controls to specific standard requirements with pass/fail/partial status

## Best practices

- Always tailor advice to the stated environment and constraints
- Flag when professional legal or regulatory review is recommended
- Avoid sharing or requesting real credentials, tokens, or sensitive system details
- Clearly distinguish between general guidance and organization-specific requirements that need customization
